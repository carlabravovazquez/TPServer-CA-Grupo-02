# 1.3. Configuración del hostname

## Objetivo

Establecer el nombre del servidor como `TPServer` y verificar que la configuración se mantenga después del reinicio del sistema operativo.

## Procedimiento

### Concepto

El *hostname* es el nombre interno que identifica a una máquina; durante la instalación de Debian se define como parte de la configuración del sistema (Universidad de Palermo, s. f., *Descarga de Linux*, p. 15). En la VM de la cátedra el nombre era `debian`.

### Búsqueda del comando adecuado

El comando `hostnamectl` no figura en los apuntes ni en el libro de la materia. Para llegar a él se usaron únicamente herramientas de la bibliografía: el autocompletado con Tab, `whatis` y el manual (`man`). Tanto el apunte *Comandos* (p. 1) como Niklas (2020, p. 60) indican consultar `man` para aprender a usar un comando.

**1. Autocompletado con Tab.** Se escribió `host` y se presionó **Tab dos veces**. Bash listó todos los comandos que comienzan con esas letras: `host`, `hostid`, `hostname` y `hostnamectl` (Universidad de Palermo, s. f., *Comandos*, p. 1; Niklas, 2020, p. 49). Como no se presionó Enter, esta acción no queda registrada en el `history`.

**Figura 1.** Autocompletado de `host` con Tab Tab. En la pantalla también se ve el sistema antes del cambio: `Debian GNU/Linux 11 debian tty1`.

![Tab Tab](Capturas/Captura%2001.12.png)

**2. Descripción breve con `whatis`** (Universidad de Palermo, s. f., *Comandos*, p. 3):

```bash
whatis hostname hostnamectl
```

El resultado muestra `hostname (1)`: define o muestra el nombre de un equipo; `hostname (5)`: archivo de configuración del hostname local; `hostname (7)`: descripción de la resolución de nombres; y `hostnamectl (1)`: *Control the system hostname*. El número entre paréntesis es la sección del manual: 1 = comandos de usuario, 5 = formatos de archivos de configuración, 7 = miscelánea (Niklas, 2020, pp. 60–61).

**Figura 2.** Salida de `whatis`.

![whatis](Capturas/Captura%2001.13.png)

**3. Manual de `hostnamectl`.**

```bash
man hostnamectl
```

La sección DESCRIPTION indica que el comando *may be used to query and change the system hostname* (sirve para consultar y cambiar el nombre del sistema) y que el nombre estático se guarda en `/etc/hostname`.

**Figura 3.** Manual de `hostnamectl`.

![man hostnamectl](Capturas/Captura%2001.14.png)

Dentro del manual se escribió **`/set-hostname`** y se presionó Enter. La barra `/` busca un texto hacia adelante, igual que en `vi` (Universidad de Palermo, s. f., *Editores de texto*, p. 4). Se encontró la opción **`set-hostname NAME`**: *Set the system hostname to NAME*. Para salir del manual se presionó **`q`** (Niklas, 2020, p. 60).

**Figura 4.** Búsqueda de la opción `set-hostname` dentro del manual.

![set-hostname en el manual](Capturas/Captura%2001.15.png)

**4. Manual de `hostname`: justificación de la edición de `/etc/hosts`.**

```bash
man hostname
```

Dentro del manual se buscó **`/etc/hosts`** + Enter. El manual (en español) explica que el nombre del equipo se asocia a una dirección en `/etc/hosts`, con el ejemplo `127.0.1.1 ursula.example.com ursula`, y que es habitual modificarlo en ese archivo. Este archivo cumple la función de traducir nombres a direcciones IP de forma local, concepto explicado en el apunte *DNS-DHCP* (Universidad de Palermo, s. f., p. 1). Salida con **`q`**.

**Figura 5.** Manual de `hostname`.

### Modificación del hostname

Se consultó el estado inicial:

```bash
hostnamectl
```

```text
Static hostname: debian
Operating System: Debian GNU/Linux 11 (bullseye)
Kernel: Linux 5.10.0-30-amd64
```

**Figura 7.** Hostname inicial `debian`.

![hostnamectl inicial](Capturas/Captura%2001.18.png)

Se cambió el nombre y se volvió a consultar:

```bash
hostnamectl set-hostname TPServer
hostnamectl
```

- `hostnamectl`: herramienta que consulta y cambia el nombre del sistema.
- `set-hostname`: opción encontrada en el manual para establecer un nombre nuevo.
- `TPServer`: nombre pedido por la consigna, respetando mayúsculas y minúsculas.

`set-hostname` no muestra ningún mensaje: en GNU/Linux, que un comando no muestre nada suele significar que terminó sin errores. La segunda consulta mostró `Static hostname: TPServer`.

**Figura 8.** En una misma pantalla: estado anterior, comando `set-hostname` y verificación con `Static hostname: TPServer`.

![set-hostname](Capturas/Captura%2001.19.png)

**Observación:** el prompt sigue diciendo `root@debian`. Es normal: el prompt toma el nombre del equipo cuando se inicia la sesión, así que cambia en el próximo inicio de sesión o reinicio. El cambio ya está aplicado, como confirma `hostnamectl`.

### Actualización del archivo `/etc/hosts`

Se consultó el archivo sin modificarlo (Universidad de Palermo, s. f., *Comandos*, p. 3; `/etc` contiene la configuración del sistema, *El standard FHS*, p. 2):

```bash
cat /etc/hosts
```

La línea `127.0.1.1  debian.up  debian` todavía tenía el nombre anterior.

**Figura 9.** Contenido de `/etc/hosts` antes de editarlo.

![cat /etc/hosts antes](Capturas/Captura%2001.20.png)

Se editó el archivo con `vi` (Universidad de Palermo, s. f., *Editores de texto*, pp. 2–4):

```bash
vi /etc/hosts
```

`vi` siempre se abre en **modo comando**: las teclas son órdenes, no texto. Para escribir hay que pasar a **modo inserción** con `i`, y para volver al modo comando se presiona `Esc`.

**Figura 10.** Archivo original abierto en `vi`.

![vi original](Capturas/Captura%2001.21.png)

Secuencia exacta de teclas:

| # | Tecla | Qué hace | Modo |
|---|---|---|---|
| 1 | **↓** hasta la línea `127.0.1.1` | Ubica el cursor en la línea a modificar | Comando |
| 2 | **→** hasta la `d` de `debian.up` | Ubica el cursor al comienzo del primer nombre | Comando |
| 3 | **`i`** | Pasa a modo inserción (abajo aparece `-- INSERTAR --`) | Comando → Inserción |
| 4 | Escribir `TPServer.up` | Inserta el nombre nuevo **antes** del viejo | Inserción |
| 5 | **Esc** | Vuelve a modo comando (el cursor retrocede un lugar) | Inserción → Comando |
| 6 | **→** | Deja el cursor sobre la `d` de `debian.up` | Comando |
| 7 | **`x`** ×9 | Borra los 9 caracteres de `debian.up`, de a uno | Comando |
| 8 | **→** hasta la `d` del último `debian` | Ubica el cursor en el segundo nombre | Comando |
| 9 | **`i`**, escribir `TPServer`, **Esc** | Inserta el nombre corto | Comando → Inserción → Comando |
| 10 | **→** y **`x`** ×6 | Borra `debian` (6 caracteres) | Comando |
| 11 | **`:wq`** + Enter | `:` abre la línea de órdenes; `w` guarda; `q` sale | Línea de órdenes |

La tecla `x` borra el carácter que está debajo del cursor (Universidad de Palermo, s. f., *Editores de texto*, p. 3).

**Técnica usada (importante para repetirlo):** primero se inserta el texto nuevo y después se borra el viejo. Si se borra primero hasta el final de la línea, el cursor queda sobre el tabulador anterior y `i` inserta *antes* de él, con lo que el nombre queda pegado a la IP.

**Figura 11.** Línea ya editada, todavía en modo inserción (`-- INSERTAR --`).

![vi editado](Capturas/Captura%2001.22.png)

**Figura 12.** Orden `:wq` escrita en la línea de órdenes, antes de presionar Enter.

![:wq](Capturas/Captura%2001.23.png)

Al guardar, `vi` confirmó `"/etc/hosts" 7L, 200B escritos` (7 líneas, 200 bytes). Se verificó con `cat`:

```bash
cat /etc/hosts
```

```text
127.0.1.1   TPServer.up   TPServer
```

**Figura 13.** Confirmación de guardado y contenido final de `/etc/hosts`.

![cat /etc/hosts después](Capturas/Captura%2001.24.png)

### Reinicio y verificación

Se reinició el sistema (Universidad de Palermo, s. f., *Comandos*, p. 3):

```bash
shutdown -r now
```

`-r` significa reiniciar (*reboot*) y `now`, de inmediato.

**Figura 14.** Reinicio con `shutdown -r now`.

![shutdown -r now](Capturas/Captura%2001.25.png)

Después del reinicio, la pantalla de inicio de sesión ya muestra el nombre nuevo: `Debian GNU/Linux 11 TPServer tty1` y `TPServer login:`. Al ingresar como `root`, el prompt pasó a ser `root@TPServer:~#` y el kernel se identifica como `Linux TPServer 5.10.0-30-amd64`. El nombre se mantuvo después del reinicio, como pide la consigna.

**Figura 15.** Inicio de sesión después del reinicio con el hostname `TPServer`.

![login TPServer](Capturas/Captura%2001.26.png)

### Registro de comandos (`history`)

Se ejecutó `history`, que muestra los comandos ejecutados en orden (Niklas, 2020, p. 58).

**Figura 16.** Salida de `history` al terminar el punto 1.3.

![history](Capturas/Captura%2001.27.png)

Cómo se lee:

- **Líneas 1 a 8** (`history`, `history -w`, `rm -f /root/.bash_history`, `journalctl --rotate`, `journalctl --vacuum-time=1s`, `apt clean`, `sync`, `poweroff`): no son del grupo. Son los comandos con los que **la cátedra limpió la VM** antes de distribuirla.
- **Línea 9** (`shutdown -h now`): cierre de la sesión de verificación del punto 1.2. `passwd` y `exec /sbin/init` no aparecen porque se ejecutaron en el Bash mínimo de `init=/bin/bash`, que no guarda historial.
- **Líneas 10 a 20**: el punto 1.3 en el orden real: `whatis` → `man hostnamectl` → `man hostname` → `hostnamectl` → `set-hostname` → `hostnamectl` → `cat` → `vi` → `cat` → `shutdown -r now` → `history`. **Muestra que la búsqueda del comando (`whatis`, `man`) se hizo antes de usarlo.** El Tab Tab no figura porque no se presionó Enter.

## Problemas encontrados y solución

El comando `hostnamectl` y la edición del archivo `/etc/hosts` no figuran en los apuntes ni en el libro de la cátedra. Para no usar un comando sin fundamento, se llegó a ellos con herramientas que sí enseña la bibliografía: el autocompletado con **Tab Tab** para descubrir los comandos disponibles, `whatis` para conocer su función y `man` para leer cómo se usan. Cada uno de esos pasos quedó documentado con una captura.

Después de ejecutar `hostnamectl set-hostname`, el prompt siguió mostrando `root@debian`, lo que podía hacer pensar que el cambio no se había aplicado. No era un error: el prompt toma el nombre del equipo al iniciar la sesión. Se confirmó el cambio con `hostnamectl` y, finalmente, con el reinicio.

Por último, al editar `/etc/hosts` con `vi` existía el riesgo de que el nombre nuevo quedara pegado a la dirección IP si se borraba primero el texto viejo hasta el final de la línea. Para evitarlo se insertó primero el nombre nuevo y recién después se borró el anterior.

## Resultado

El servidor quedó identificado como `TPServer`, tanto en la configuración del sistema (`hostnamectl`, `/etc/hostname`) como en la resolución local de nombres (`/etc/hosts`). El nombre se mantuvo después del reinicio.

**Instantánea de VirtualBox:** `02 - Punto 1.3 hostname TPServer`.

**Dato útil:** **Ctrl + L** limpia la pantalla de la terminal (Niklas, 2020, p. 49).
