# 2.3. Servidor web Apache con soporte PHP

## Objetivo

Instalar el servidor web Apache con soporte para PHP 7.3 o superior, publicar los archivos `index.php` y `logo.png` del material de la cátedra y comprobar el funcionamiento desde la computadora física.

## Conceptos previos

- **Apache** (`apache2` en Debian) es un servidor web: recibe pedidos de navegadores por el protocolo HTTP (puerto 80) y devuelve archivos.
- **PHP** es un lenguaje que se ejecuta en el servidor: Apache, a través del módulo `libapache2-mod-php`, ejecuta el archivo `.php` y envía al navegador solo el resultado (HTML).
- **`php-mysql`** es la extensión que permite a PHP conectarse a MySQL/MariaDB. Es imprescindible porque `index.php` se conecta a la base de datos con `MySQLi` (punto 2.4).
- Apache corre con el usuario de servicio **`www-data`**, cuyo directorio es `/var/www` (Universidad de Palermo, s. f., *Administración de usuarios*, pp. 2–3).
- Los archivos de configuración están en `/etc/apache2` (Universidad de Palermo, s. f., *El standard FHS*, p. 2).

Los nombres de los paquetes no figuran en los apuntes: se buscaron con `apt-cache search` y se verificaron con `apt show` (*Gestor de software*, pp. 5 y 9), así que el camino para encontrarlos sí sale de la bibliografía.

## Procedimiento

### Paso 1: verificación de las versiones disponibles

```bash
apt show apache2
```

`apt show` muestra la información de un paquete (Universidad de Palermo, s. f., *Gestor de software*, p. 9). Versión `2.4.68-1~deb12u1`, del repositorio `bookworm/main`. Al final aparece la nota `N: Hay 1 registro adicional. Utilice la opción «-a» para verlo`.

**Figura 1.** Información del paquete `apache2`.

![apt show apache2](Capturas/Captura%2002.51.png)

```bash
apt show -a apache2
```

Con `-a` (*all*) muestra todas las versiones: **2.4.68-1~deb12u1** (`bookworm/main`) y **2.4.67-1~deb12u3** (`bookworm-security/main`). La nota solo significa que el paquete está en dos de los repositorios configurados en `sources.list` (punto 2.1); `apt` instala la versión más nueva (*Gestor de software*, pp. 2–3 y 9).

**Figura 2.** Las dos versiones de `apache2`.

![apt show -a](Capturas/Captura%2002.52.png)

```bash
apt show php
```

`Depends: php8.2` (*currently 8.2*): la versión de PHP es **8.2**, que **cumple el requisito de 7.3 o superior**.

**Figura 3.** Versión de PHP disponible.

![apt show php](Capturas/Captura%2002.53.png)

### Paso 2: búsqueda de los módulos

```bash
apt-cache search libapache2-mod-php
apt-cache search php-mysql
```

Resultados: `libapache2-mod-php` (*server-side, HTML-embedded scripting language (Apache 2 module)*) y `php-mysql` (*MySQL module for PHP*) (*Gestor de software*, p. 5). (`php-mysql` se buscó dos veces.)

**Figura 4.** Búsqueda de los módulos.

![apt-cache search](Capturas/Captura%2002.54.png)

### Paso 3: instalación

```bash
apt-get install apache2 php libapache2-mod-php php-mysql
```

Se pueden instalar varios paquetes en un solo comando, separados por espacios (*Gestor de software*, p. 4). Propuso 23 paquetes nuevos (7371 kB); se respondió **`S`** + Enter.

**Figura 5.** Resumen de la instalación.

![apt-get install](Capturas/Captura%2002.55.png)

Durante la configuración aparecen `Enabling module php8.2`, `Switch to mpm prefork` y `Enabling site 000-default`: Apache habilita PHP automáticamente y activa el sitio por defecto.

**Figura 6.** Fin de la instalación.

### Paso 4: primera prueba desde la computadora física

En el navegador de Windows se ingresó `http://192.168.0.209` y apareció **"Apache2 Debian Default Page – It works!"**. La consigna pide expresamente probar desde la máquina física (Consigna, p. 2). La advertencia "No es seguro" del navegador indica que la conexión es `http` sin certificado (la consigna no pide `https`).

**Figura 8.** Página por defecto de Apache vista desde Windows.

![It works](Capturas/Captura%2002.58.png)

### Paso 5: publicación de los archivos

```bash
grep DocumentRoot /etc/apache2/sites-available/000-default.conf
```

`DocumentRoot /var/www/html`: es la carpeta cuyo contenido publica Apache (*Streams y filtros*, p. 3; Niklas, 2020, p. 254).

**Figura 9.** Carpeta publicada por Apache.

![DocumentRoot](Capturas/Captura%2002.59.png)

```bash
ls -l /var/www/html
cp /root/Material_Adicional_TPVMCA/index.php /root/Material_Adicional_TPVMCA/logo.png /var/www/html/
mv /var/www/html/index.html /var/www/html/index.html.orig
ls -l /var/www/html
```

- `cp origen1 origen2 destino/` copia los dos archivos a la carpeta (*Comandos*, p. 2).
- `mv` renombra `index.html`: Apache, cuando se pide `http://IP/`, entrega primero `index.html` si existe. Se lo renombró en lugar de borrarlo, para conservarlo (*Comandos*, p. 2).

Antes había solo `index.html`; después: `index.html.orig`, `index.php` (2325 B) y `logo.png` (1719 B), con permisos `-rw-r--r--`. El último `r` (lectura para "otros") permite que el usuario `www-data` los lea (*Permisos – Formato octal*, pp. 3–4).

**Figura 10.** Archivos publicados.

![cp mv](Capturas/Captura%2002.60.png)

### Paso 6: prueba y lectura del registro de errores

`http://192.168.0.209/logo.png` muestra el logo de la UP: Apache entrega archivos de la carpeta.

**Figura 11.** Logo servido a la computadora física.

![logo](Capturas/Captura%2002.61.png)

`http://192.168.0.209` muestra una **página en blanco**. Es el resultado esperado: `index.php` necesita la base de datos, que se instala en el punto 2.4.

**Figura 12.** Página en blanco antes de instalar la base de datos.

![blanco](Capturas/Captura%2002.62.png)

```bash
grep PHP /var/log/apache2/error.log
```

Apache registra los errores en `/var/log/apache2/error.log` (*El standard FHS*, p. 3). Resultado:

```text
[php:error] [client 192.168.0.34] PHP Fatal error: Uncaught mysqli_sql_exception:
No such file or directory in /var/www/html/index.php:11
```

**Figura 13.** Error de PHP registrado por Apache.

![error.log](Capturas/Captura%2002.63.png)

Lectura del error (para la defensa):

- `client 192.168.0.34` es la computadora con Windows.
- `[php:error]` demuestra que **PHP ejecutó el archivo**. Si PHP no funcionara, el navegador mostraría el código fuente o descargaría el archivo.
- La línea 11 de `index.php` intenta conectarse a la base con `new MySQLi("localhost", "lcars", …, "ingenieria")`.
- *No such file or directory* indica que no existe el socket de MariaDB, porque todavía no está instalada.
- La página queda en blanco porque Debian no muestra los errores de PHP al visitante: los registra en el log.

## Problemas encontrados y solución

No se presentaron problemas. La página en blanco que se obtuvo al final es el comportamiento esperado: `index.php` necesita la base de datos, que se instala en el punto 2.4, y el registro de errores de Apache confirmó que PHP funcionaba correctamente.

## Resultado

Apache 2.4 con PHP 8.2 quedó instalado y activo, sirve `logo.png` a la computadora física y ejecuta `index.php`.

**Instantánea de VirtualBox:** `05 - Punto 2.3 Apache PHP`. El `history` de este punto quedó completo (líneas 54–68) porque se apagó con `shutdown -h now`.
